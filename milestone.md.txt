## Still Needs Review

- Visual review of spacing, copy, Albanian wording, product imagery, and exact AuctionSq brand tone.
- Admin pages are functional and organized, but edit flows are still mostly list/create/action based rather than full dedicated add/edit detail screens.
- Product image upload storage is not yet a polished upload UI; current admin product creation accepts image URLs.
- Auth flows should be tested with real Supabase users, including admin role assignment and password reset emails.
- Live bid behavior should be reviewed with multiple accounts before launch.

## What Should Be Tested Next

1. Register a new user and confirm the profile completion requirement before bidding.
2. Log in as an admin user and test product creation, auction creation, bid moderation, order status updates, category creation, and audit logs.
3. Place bids on active auctions with two users and verify current price, bid count, and dashboard states.
4. Run the expired-auction closer and verify winner/order creation.
5. Test mobile layouts for home, auctions, auction detail, dashboard, and admin tables.
6. Decide whether product image upload should use Supabase Storage before deployment.

## Important Decisions

- AuctionSq remains an admin-controlled auction platform, not a marketplace.
- Only admins can create products and auctions.
- Users must be logged in and have complete delivery details before bidding.
- Supabase is the source of truth for live data; local memory data remains a fallback for sandbox/dev behavior.
- Vercel setup is intentionally left for later, per user instruction.
